# Correction contract

Every apparatus PASS/FAIL must derive from a closed graph of unique question, requirement, gate, contract, comparison, prediction interval, measurement, uncertainty, classification, evidence, and result records. All IDs and contexts must match. Dangling, duplicate, wrong-type, stale, cross-case/channel/requirement/gate, incompatible-contract, nonfinite, or malformed evidence raises validation failure; it is never a scientific state.

Legitimate incomplete evidence or missing required uncertainty is `UNRESOLVED`; no relevant matched comparator is `NOT_EVALUATED`; frozen inapplicability alone is `NOT_APPLICABLE`. Caller classification, gate result, apparatus aggregate, or terminal status is never authoritative. Dynamic/spatial selection consumes only internally derived apparatus state.

The actual pilot is expected, not forced, to remain additional-data-required. Physical validation remains `NOT_ESTABLISHED`.
