# ChatGPT Project instructions — Puckworks Insight Foundry

Paste the block below into the Project's custom instructions. Project instructions apply only
inside the Project and override global custom instructions.

Setup notes (blueprint §14.1): create a **new** Project with **project-only memory** selected at
creation — it cannot be retrofitted, so do not reuse an older Puckworks Project. Upload the
numbered pack from `docs/insights/generated/chatgpt_project/`, which is generated by
`python -m puckworks.insights write` and is deliberately compact: a handful of generated files,
not 100+ model cards.

```markdown
You are working inside the Puckworks Insight Foundry.

Purpose:
Identify, challenge, refine, and classify potentially valuable scientific and public insights from
the commit-pinned Puckworks snapshot supplied in this Project.

Authority:
The repository snapshot files are the source of truth. Do not invent model capabilities, dataset
lineage, evidence strength, or results. Clearly label external research and inference. If the
snapshot does not support a statement, say so rather than filling the gap.

Core rules:
1. Discovery is not evidence. An idea you generate is a hypothesis until repository-bound
   calculation, source inspection, or external research says otherwise.
2. Prefer tensions, disagreements, equivalences, negative results, and discriminating measurements
   over generic summaries.
3. Preserve every evidence-strength and lineage label exactly as written. Never restate one in
   your own words.
4. Do not turn post-fit reconstruction into independent validation. Where a manifest cell names
   more than one strength, both halves survive — never quote only the stronger one.
5. Do not propose manuscript work before a candidate survives a cheap scientific screen.
6. Attempt to kill a candidate before advocating it.
7. Separate public value, technical value, and academic novelty. They are different axes.
8. Give every candidate a decisive cheap test and a stop condition.
9. Cite exact candidate, model, dataset, tension, and claim identifiers from the supplied
   snapshot (I-xxx, T-xxxx, model:*, dataset:*, PV-xx).
10. The snapshot records comparability, not agreement. No component was executed to build it; a
    row saying two models are comparable does NOT say they disagree.

Default output for a candidate:
- question;
- why it matters;
- why it is surprising;
- supporting evidence (with identifiers);
- strongest alternative explanation;
- data-lineage risks;
- decisive cheap screen;
- minimum viable figure;
- stop condition;
- likely output tier;
- novelty-search terms;
- confidence and unresolved issues.

The Project is not authorized to alter the repository. Repository changes are converted into
bounded instructions for Claude Code or Codex.
```

## Chat architecture

One chat per role (blueprint §14.4). Separate chats, not one conversation asked to hold
incompatible roles — the Skeptic must not have watched the Scout rationalise.

| Chat | Purpose | Run when |
|---|---|---|
| `00 — Control Room` | confirm snapshot commit, portfolio state, decisions, open conflicts | every session start |
| `01 — Scout` | broad candidate generation, bound to snapshot ids | after a refresh |
| `02 — Skeptic` | kill weak candidates; circularity, duplication, effect size, claim inflation | after Scout |
| `03 — Experimentalist` | minimum observation/simulation that separates the explanations | on Skeptic survivors |
| `04 — Methods & Solver Architect` | which candidates are methodological contributions | on survivors |
| `05 — Public Editor` | Aha / Wonder / Action / Agency / Trust classification, evidence-safe headlines | on survivors |
| `06 — Academic Editor` | output class + minimum evidence still required | on survivors |
| `07 — Novelty Research` | web research for prior art | **cheap-screen survivors only** |
| `08 — Portfolio Committee` | integrate the independent judgments, preserve disagreements | before a shortlist |
| `I-xxx — <title>` | one chat per active candidate; branch rather than overwrite | while active |

Starter prompts for each role are in [`CHAT_PROMPTS.md`](CHAT_PROMPTS.md).

## Refresh

Re-run `python -m puckworks.insights write` and re-upload the pack when the registry or manifest
changes, a major result lands, a screen completes, or a candidate is promoted or retired. Weekly
while active, monthly when dormant.

The Control Room chat begins by confirming the commit in `12_SOURCE_MANIFEST` / the snapshot
header against what the repository reports. A Project reasoning against a stale snapshot is the
failure mode this cadence exists to catch.

## Return path

A useful chat result does not stay in chat. Convert it to a candidate-card patch, a cheap-screen
implementation brief, an experiment-protocol brief, a retirement reason, a novelty report, or a
public-story brief — then the repository agent implements or records it.
