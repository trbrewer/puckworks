## 2. Executive implementation decision

### 2.1 Adopt the review’s Path A: a criterion-free descriptive conclusion

The manuscript should **not** retain “no resolvable skill,” “no resolvable gain,” or “unresolved throughout the declared tolerance.” No predeclared practical margin, equivalence margin, inferential decision rule, or calibrated coverage procedure defines what “resolvable” means. Adding such a threshold after seeing the result would create a post hoc decision rule and would be harder to defend than the current analysis.

The supported conclusion is narrower and scientifically stronger:

> The mechanistic model showed a small and uneven observed pooled-error advantage over the trained level-only comparator. The fixed-predictor clustered sensitivity ranges are not calibrated confidence intervals, and no practical relevance or equivalence margin was prespecified. The comparison therefore does not establish statistical superiority, non-superiority, equivalence, practical materiality, or transferable mechanistic skill. Acceptable endpoint prediction does not, by itself, establish mechanism transfer.

This wording preserves all of the paper’s useful conclusions without asserting that incremental predictive skill is absent.

### 2.2 Do not change the headline numerical results unless an independent check demonstrates a defect

The Round 10 review found the current headline values internally consistent. The intended correction is therefore **numerically invariant**:

- model pooled MAPE at 40 g: `8.44%`;
- comparator pooled MAPE at 40 g: `8.83%`;
- paired difference: `−0.394 pp`;
- model worse on `62 of 132` observations;
- primary full-precision ranges at 38/40/42 g unchanged;
- secondary-scheme ranges unchanged;
- audit values and scope unchanged;
- corpus size and scheme membership unchanged.

No scientific artifact rewrite and no PDE re-solve should be needed if the implementation follows this plan. Run `paper_a_transfer_artifacts.py --write` only if the artifact’s persisted structure or values must change and only after a slow recomputation has been separately adjudicated.

### 2.3 Preserve schema version 3 unless persisted field meaning changes

The recommended changes strengthen validation and rendering but do not alter the persisted artifact shape or the meaning of existing fields. Therefore:

- keep `SCHEMA_VERSION = 3` if outputs remain structurally identical;
- do **not** bump the schema merely because validation becomes stricter;
- bump the schema only if a new persisted observation ledger, new audit field, renamed field, or changed field meaning is introduced;
- if a schema bump becomes necessary, treat it as a separate scientific-governance decision and regenerate all affected artifacts atomically.

## 3. Non-negotiable implementation constraints

1. **Edit source files, not generated copies.** Generated manuscript, package, Highlights, cover letter, draft, supplement blocks, and generated captions must be regenerated by their owning tools.
2. **One authority per fact.** Full-precision interval bounds determine interval geometry through `transfer_semantics.py`; cached Booleans may be validated but must not drive publication prose.
3. **The independent oracle must remain independent.** It may share domain constants only where unavoidable, but it must not import production grouping functions or derive its expected observation universe from the artifact.
4. **Validators fail closed with named diagnostics.** Validation functions must return problem lists for malformed external data; strict accessors may raise only controlled, contextual exceptions.
5. **No inference laundering.** Do not replace the retired wording with “not statistically significant,” “equivalent,” “no difference,” “no skill,” or “no effect.” None is established by the present procedure.
6. **Do not cherry-pick range geometry.** Wholly negative and zero-containing sensitivity ranges must be treated symmetrically as non-calibrated sensitivity results.
7. **Protect numerical invariance.** Capture a machine-readable before/after comparison of all headline scientific fields.
8. **Do not widen scope.** Do not reopen the explicitly out-of-scope metadata, novelty search, release DOI, known open scientific items, Papers B2/3, or settled endpoint/Reynolds/flow questions.

# 5. P0-1 — Remove the unsupported “no resolvable skill” verdict

## 5.1 Objective

Replace a positive no-skill/no-resolution verdict with the strongest conclusion actually supported by the design:

- the observed aggregate advantage is small and uneven;
- the model loses on roughly half of individual observations despite lower pooled MAPE;
- sensitivity-range geometry changes with endpoint and scheme;
- the ranges have no calibrated coverage;
- no practical relevance or equivalence margin was declared;
- acceptable endpoint accuracy does not establish transferable mechanistic skill.

The correction must be consistent across every submission-facing representation, not only the manuscript body.

## 5.2 Method

### Step 1 — Record the interpretation decision in code comments and the PR description

State explicitly that the revision adopts a **criterion-free interpretation**. Do not add an arbitrary numerical cutoff for “resolvable.” The decision record should explain:

- why a post hoc threshold would be circular;
- why zero containment/non-containment is descriptive rather than inferential here;
- why “does not establish mechanism transfer” is not equivalent to “establishes no incremental skill.”

This prevents a later editor from restoring the shorter but unsupported wording.

### Step 2 — Update the single front-matter source

Edit `docs/submission/paper_a_front_matter.yaml`, not its generated renderings.

#### Recommended abstract replacement

Replace:

> “…the model was worse on 62 of 132 observations — no resolvable skill beyond a transferred level.”

with:

> “…the model was worse on 62 of 132 observations. This small, uneven observed advantage did not establish transferable mechanistic skill.”

The complete corrected sentence should read:

> The paired difference was −0.394 percentage points; the primary clustered percentile range (−0.829 to +0.004) contained zero and the model was worse on 62 of 132 observations. This small, uneven observed advantage did not establish transferable mechanistic skill.

This version keeps every current number, avoids treating zero containment as a significance test, and remains concise. It is expected to leave the abstract within the 250-word venue limit, but the repository’s own word counter is authoritative and must be run.

#### Recommended editor-significance replacement

Replace the clause:

> “…while adding no resolvable skill over a trained level-only baseline.”

with two explicit sentences:

> “…while showing only a small, uneven observed advantage over a trained level-only baseline. Because the fixed-predictor sensitivity ranges are not calibrated confidence intervals and no practical margin was specified, that comparison does not establish transferable mechanistic skill or practical materiality.”

#### Recommended Highlight refinement

The existing “barely outperformed” wording is not itself a formal Round 10 finding, but it can be made more consistent and less inferential:

> A process model showed only a small advantage over a concentration-only baseline

This is 80 characters and should remain below the 85-character limit. Retain the existing Highlight only if the front-matter test confirms the whole set and a prose review finds no implication of calibrated superiority.

### Step 3 — Correct the generated transfer-result source

Edit `tools/paper_a_transfer_text.py`.

#### `block_transfer_headline()`

Retain the descriptive values and replace the last sentence with:

> The small observed aggregate advantage therefore does not, by itself, establish transferable mechanistic skill beyond a trained concentration level.

Do not use “did not supply skill,” because that again reads as a positive absence claim.

#### `block_endpoint_reading()`

Restructure the reading so that it separates three questions rather than forcing them into a single “unresolved” verdict:

1. **Observed effect:** magnitude and observation-level heterogeneity.
2. **Sensitivity geometry:** which ranges are below or contain zero.
3. **Permitted inference:** what the non-calibrated procedure does and does not establish.

Recommended final interpretation paragraph:

> The supported conclusion is deliberately narrower than a no-skill verdict. At the canonical draw count, some declared ranges exclude zero on the negative side and others contain zero. Because these are fixed-predictor sensitivity ranges without calibrated coverage, neither pattern establishes statistical superiority, non-superiority, equivalence, practical materiality, or absence of incremental skill. No practical relevance or equivalence margin was prespecified. Taken together with the small pooled-error difference and mixed observation-level signs, the result shows that acceptable endpoint prediction does not, by itself, establish transferable mechanistic skill beyond a trained concentration level.

Also change the opening “Two things follow, and they agree” if needed. A better structure is:

> Three observations should be kept separate.

This prevents the section from implying that descriptive facts jointly prove a no-skill result.

Retain useful descriptive content such as:

- the paired difference range;
- the contrast with the blind residual’s movement;
- the model-worse counts;
- the actual trinary range relations;
- the estimand direction;
- the favourable and least-favourable bounds;
- the audit-scope caveat.

Remove or rewrite:

- “No row supports a claim of resolvable skill”;
- “unresolved throughout the declared tolerance”;
- “permit none at all” when used as an inferential conclusion rather than a geometric description;
- any sentence that treats containing zero as evidence of non-superiority.

#### Supplementary Table S3 reading

Replace the sentence ending in “the benchmark is therefore reported as unresolved throughout the declared tolerance” with:

> The model-minus-comparator point difference remains negative and small across the endpoint sweep, while the primary range excludes zero at 38 g and contains zero at 40 and 42 g; secondary-scheme ranges provide additional dependence sensitivities. These are fixed-predictor sensitivity ranges, not calibrated confidence intervals. Without calibrated coverage or a prespecified practical margin, their geometry does not establish superiority, non-superiority, equivalence, practical materiality, or absence of incremental skill. The supported conclusion is that acceptable endpoint error does not, by itself, establish transferable mechanistic skill.

The exact wording may be shortened, but all four epistemic distinctions must remain.

### Step 4 — Correct cover-letter generation

Edit `tools/paper_a_front_matter.py`, not `PAPER_A_JFE_COVER_LETTER.md` directly.

Replace:

### Step 7 — Add an explicit no-overreach consistency guard

Extend `tools/paper_a_consistency.py` or a dedicated Paper A interpretation check to scan all submission-facing outputs and relevant generator literals for the retired formulations.

## 5.3 Potential pitfalls, errors, and oversights

1. **Substituting “not significant.”** The present range is not a calibrated significance interval.
2. **Substituting “equivalent.”** No equivalence margin or TOST-style procedure exists.
3. **Substituting “no difference.”** The point estimate is not zero and is negative at every endpoint.
4. **Using only the primary 40 g range.** Secondary ranges and the 38 g primary range are wholly negative; all geometry must be treated under the same no-coverage rule.
5. **Describing the advantage as practically negligible without a margin.** “Small in absolute pp” is descriptive; “immaterial” requires a declared decision context.
6. **Deleting the model-worse count.** It is valuable evidence of uneven observation-level performance and should remain.
7. **Overstating the model’s benefit.** The correction must not swing from no-skill overreach to a superiority claim.
8. **Editing generated files directly.** Such edits will be overwritten and will create drift.
9. **Exceeding the abstract or Highlight limits.** Run the repository’s exact counters.
10. **Leaving stale wording in the package, cover letter, supplement, or caption map.** The P0 is not closed until every surface is corrected.
11. **Treating `small_sign_stable_effect_boundary_not_stable` as a no-skill code.** Its meaning should remain descriptive.
12. **Changing headline numbers during a prose correction.** Any numerical movement is a stop condition requiring separate adjudication.

# 6. P1-1 — Make typed semantics the sole authority for interval geometry

## 6.1 Objective

Ensure every publication sentence about an interval’s relation to zero is derived from full-precision bounds through `puckworks.paper_a.transfer_semantics`, never from cached `contains_zero_full_precision` or `excludes_zero_full_precision` fields.

Cached fields may remain in artifacts for compatibility and validation. They must not be an independent publication authority.

## 6.2 Method

### Step 1 — Refactor `block_endpoint_reading()`

Replace the current direct Boolean reads with typed objects:

```python
pairs = [
    (
        m,
        TS.from_interval_record(
            scheme_interval(row, TC.PRIMARY_SCHEME)
        ),
    )
    for m, row in sorted(rows.items())
]

below = [m for m, sem in pairs if sem.relation is TS.ZeroRelation.BELOW]
contains = [m for m, sem in pairs if sem.relation is TS.ZeroRelation.CONTAINS]
above = [m for m, sem in pairs if sem.relation is TS.ZeroRelation.ABOVE]
```

Do not create `excludes = not contains`; that would again collapse `BELOW` and `ABOVE` into one Boolean state.

Render the sweep using an explicit relation summary. Either add a pure helper to `transfer_semantics.py` or keep a small renderer helper that consumes typed `IntervalSemantics` values only. A suitable interface is:

```python
def group_endpoints_by_relation(pairs):
    return {
        TS.ZeroRelation.BELOW: [...],
        TS.ZeroRelation.CONTAINS: [...],
        TS.ZeroRelation.ABOVE: [...],
    }
```

The helper must not inspect archived flags.

### Step 2 — Search all publication renderers

Search all Paper A generator code for direct reads of the cached fields:

```bash
rg -n 'contains_zero_full_precision|excludes_zero_full_precision' \
  tools puckworks/paper_a tests
```

Adjudicate every hit:

- **allowed:** artifact construction, artifact validation, compatibility tests;
- **not allowed:** manuscript, supplement, cover-letter, caption, package, or figure prose generation.

This review identified `block_endpoint_reading()` as a definite breach, but the correction should establish a repository-wide renderer rule rather than fixing only one line.

### Step 3 — Add an AST/static guard

Add a test that parses publication-renderer source and rejects string-key access to the cached fields. Example:

```python
def test_publication_renderers_do_not_read_cached_zero_flags():
    source = (REPO / "tools" / "paper_a_transfer_text.py").read_text(encoding="utf-8")
    tree = ast.parse(source)
    banned = {
        "contains_zero_full_precision",
        "excludes_zero_full_precision",
    }
    found = {
        node.value
        for node in ast.walk(tree)
        if isinstance(node, ast.Constant) and node.value in banned
    }
    assert not found
```

If other renderer files can make geometry claims, include them in the scanned file set. Keep the test narrow enough that validation code remains permitted to inspect the cached fields.

### Step 4 — Add contradictory-cache mutations

Create a valid-looking interval whose full-precision bounds and cached Boolean disagree. Test both layers:

1. `TC.validate_interval_record()` returns a named mismatch problem.
2. The isolated renderer, if invoked before full artifact validation, follows the typed relation derived from bounds rather than the cache.
3. The full `paper_a_transfer_artifacts.py --check` path refuses the contradictory artifact.

Example mutation:

```python

interval["excludes_zero_full_precision"] = False
```

The published relation must never become “contains zero” for these bounds.

### Step 5 — Parameterize renderer behavior over all relations

Add tests for:

- all endpoints `BELOW`;
- all endpoints `CONTAINS`;
- all endpoints `ABOVE`;
- current mixed `BELOW/CONTAINS` sweep;
- a synthetic `BELOW/CONTAINS/ABOVE` sweep;
- exact lower-bound contact at zero;
- exact upper-bound contact at zero;
- full-precision non-zero bound that displays as `0.000`.

The tests should verify both content and grammar.

## 6.3 Potential pitfalls, errors, and oversights

1. **Replacing one Boolean with another.** `relation.excludes_zero` is useful, but not sufficient when prose must name the side.
2. **Using display-rounded bounds.** Classification must use full precision only.
3. **Treating `−0.0` or `+0.0` inconsistently.** The closed-interval rule should classify exact zero as containment and record exact contact separately.
4. **Forgetting supplementary renderers or captions.** The AST guard should cover all publication-generating files.
5. **Allowing a renderer to proceed on an invalid artifact.** The full generation/check path should validate first or fail loudly.
6. **Duplicating relation-to-prose mappings.** Keep the canonical isolated prose in `ZeroRelation.prose` or a typed helper.
7. **Overfitting tests to the current 38/40/42 pattern.** Include `ABOVE` and exact-contact synthetic cases.
8. **Changing the meaning of cached fields.** They remain derived compatibility fields; do not repurpose them.

Complete the oracle’s “exact” comparison so that every normalized or documented partition field is actually checked.

The current source is complete, so this is an assurance correction rather than a numerical-result correction.

## 7.2 Method

### Step 1 — Declare an independent analyte-to-column map in the oracle

In `puckworks/paper_a/source_resampling_oracle.py`, replace the implicit “three solutes per row” assumption with an explicit independent mapping, preserving canonical order:

```python
ANALYTE_COLUMNS = (
    ("caffeine", "CF"),
    ("trigonelline", "TR"),

SOLUTES = tuple(solute for solute, _column in ANALYTE_COLUMNS)
```

The oracle must not import this map from the production grouping implementation. Independent declaration is intentional. A test should continue to enforce that the oracle does not import or call the prohibited production grouping functions.

### Step 2 — Validate analyte cells only for retained held-out rows

For every retained Arabica/Robusta coarse/fine row:

- require each mapped analyte field;
- reject empty/whitespace-only values;
- reject non-numeric values;
- reject NaN and ±infinity;
- retain enough internal information to construct the observation ID from the validated cell.

Do not fail because an irrelevant source row outside the retained held-out corpus has a missing analyte unless that row is part of another declared contract. Apply the validation after the variety/grind inclusion rule, while still requiring the header columns globally.

Suggested helper:

```python
def _finite_analyte(text, *, sample_id, solute, column):
    if text is None or not str(text).strip():
        raise ValueError(
            f"source observation {sample_id}|{solute}: column {column} is blank"
        )
    try:
        value = float(text)
    except (TypeError, ValueError) as exc:
        raise ValueError(
            f"source observation {sample_id}|{solute}: column {column} is non-numeric: {text!r}"
        ) from exc
    if not math.isfinite(value):
        raise ValueError(
            f"source observation {sample_id}|{solute}: column {column} is non-finite: {text!r}"
        )
    return value
```

Store an internal tuple such as:

```python
"observations": tuple(
    {
        "solute": solute,
        "source_column": column,
        "value": validated_value,
    }
    for solute, column in ANALYTE_COLUMNS
)
```

The values need not be persisted into the artifact; the oracle only needs them to prove source presence and scoreability.

### Step 7 — Make the top-level checker return named source-observation failures

```python
try:
```

## 7.4 Potential pitfalls, errors, and oversights

1. **Validating only headers.** A present column can still contain blank or non-finite held-out cells.
2. **Using `float()` without `math.isfinite()`.** Python accepts `NaN` and infinity.
3. **Validating all source rows indiscriminately.** Irrelevant source rows may have different completeness rules; scope validation to the declared corpus.
4. **Sharing the production mapping with the oracle.** That recreates a common-mode assumption. Independently declare and test the map.
5. **Persisting analyte values unnecessarily.** That would enlarge the schema and could require a version bump; source presence can be checked without changing artifact shape.
6. **Comparing only counts.** Counts and self-hashes cannot prove correct membership.
7. **Normalizing away a meaningful mismatch.** Sort set-like fields, but do not coerce wrong labels, wrong sample IDs, or wrong grind metadata into equivalence.
8. **Forgetting JSON key normalization.** Cluster-size keys may be strings after serialization.
9. **Catching all exceptions.** Convert only expected data-contract failures to named problems; do not hide programming errors.
10. **Running the slow writer unnecessarily.** If valid-source output is unchanged, `--check` and tests are sufficient.
11. **Changing the source data to make tests pass.** The current source is complete; the fix belongs in validation/oracle code.
12. **Claiming value validation proves scientific correctness of the values.** It proves presence/numeric finiteness and partition membership, not that the source measurements are experimentally correct.

# 10. P2-3 — Harden malformed and non-finite input handling

## 10.1 Objective

Make public validation boundaries total and diagnostic:

- validators return a list of named problems rather than raising on malformed artifact/source data;
- strict semantic/accessor functions reject invalid input through controlled `TypeError`, `ValueError`, or `KeyError` with contextual messages;
- no malformed artifact receives a false green;
- no expected malformed-data mutation produces an opaque implementation exception such as `decimal.InvalidOperation` or `AttributeError`.

## 10.2 Define the API contract first

Document and test two categories:

### Validators

Examples: `validate_endpoint_contract()`, `validate_interval_record()`, `validate_corpus_manifest()`, `validate_resampling_design()`.

Contract:

- accept arbitrary decoded JSON-like input;
- never raise for malformed external data;
- return `list[str]`;
- include a path/index and defective value/type where practical;
- may return early when the surrounding shape makes deeper validation unsafe.

### Strict accessors/classifiers

Examples: `interval_semantics()`, `from_interval_record()`, `find_exact_audit()`.

Contract:

- may raise;
- raise only controlled exceptions appropriate to the defect;
- include enough context to identify the field or list element;
- never leak `AttributeError`, `decimal.InvalidOperation`, or an uncontextualized conversion error for expected malformed inputs.

## 10.3 Method by function

### A. `validate_endpoint_contract()`

Replace the unguarded target list conversion with explicit structural and finite-number validation.

Recommended logic:

1. Require `targets` to be a list.
2. Require the expected length.
3. For each element:
   - reject Boolean explicitly (`bool` is a subclass of `int`);
   - convert in `try/except (TypeError, ValueError)`;
   - reject non-finite values with `math.isfinite()`;
   - record the index and raw value in the problem.
4. Compare exact ordered targets only if all values are valid.

Example diagnostics:

```text
endpoint.targets is str, expected a list of finite numeric masses
endpoint.targets[1] is non-numeric: 'not-a-number'
endpoint.targets[2] is non-finite: inf
endpoint.targets covers [38.0, 42.0, 40.0], expected [38.0, 40.0, 42.0] in exact order
```

Avoid adding both a conversion error and a misleading set/order mismatch for the same malformed list.

### B. `interval_semantics()`

Add strict numeric and finite checks before order/classification:

```python
for name, raw in (("lower", lower), ("upper", upper)):
    if isinstance(raw, bool):
        raise TypeError(f"interval {name} bound is boolean, expected a finite number")
    try:
        value = float(raw)
    except (TypeError, ValueError) as exc:
        raise TypeError(
            f"interval {name} bound {raw!r} is not numeric"
        ) from exc
    if not math.isfinite(value):
        raise ValueError(
            f"interval {name} bound {raw!r} is not finite"
        )
```

Then enforce `lower <= upper` and classify.

### C. `validate_interval_record()`

After extracting bounds:

- reject Booleans and non-finite values before calling `interval_record()` or display quantization;
- validate display `digits` as a sensible integer before using it;
- catch only expected conversion/formatting errors and convert them to named problems;
- do not let `Decimal('Infinity').quantize(...)` leak `InvalidOperation`.

Suggested named problems:

```text
interval.full_precision_pp.lower is non-finite: -inf
interval.display.digits is 'three', expected a non-negative integer
interval bounds are reversed (upper < lower)
```

### D. `find_exact_audit()`

Validate each list element before `.get()`:

```python
for index, audit in enumerate(audits):
    if not isinstance(audit, dict):
        raise KeyError(
            f"stability_audits[{index}] is {type(audit).__name__}, expected a mapping"
        )
```

Then match the exact target. Consider validating that each `target` is a mapping and that duplicate exact targets fail with a controlled `KeyError`.

In the top-level artifact checker, avoid adding a misleading “missing target” problem after already detecting malformed audit elements. Either skip exact lookup when the list shape is invalid or deliberately report both with clear causes.

### E. `validate_corpus_manifest()` and related validators

While implementing P1-2, make these functions robust to:

- `records` not being a list;
- record elements not being mappings;
- missing sample IDs;
- malformed solute lists;
- non-integer counts;
- Boolean values where integers are expected.

The review’s formal P2-3 examples are limited, but a consistent validator contract should cover adjacent fields touched by the same change.

## 10.4 Test matrix

Parameterize at least the following values where numeric input is expected:

```text
None
True
False
""
"not-a-number"
{}
[]
NaN
+infinity
-infinity
```

Tests should include:

- malformed top-level endpoint targets return problem lists;
- non-finite bounds are rejected by `interval_semantics()` with controlled errors;
- `validate_interval_record()` returns named problems and never raises;
- malformed audit elements cause controlled `KeyError` or a validator problem naming the index;
- reversed finite bounds remain a separate, correctly named error;
- exact zero remains valid and follows the closed-interval convention;
- valid current artifacts remain clean.

A small property-based test may be used if the project already carries the dependency. Otherwise, deterministic parameterized tests are sufficient and reduce dependency risk.

## 10.5 Potential pitfalls, errors, and oversights

1. **`bool` passing numeric checks.** Reject it explicitly.
2. **`NaN` defeating comparisons.** Always use `math.isfinite()`.
3. **Catching broad `Exception`.** This can hide real code defects and create false confidence.
4. **Validator recursion after a shape error.** Stop at the malformed parent when child access is unsafe.
5. **Returning only “invalid artifact.”** Diagnostics must identify the path/index.
6. **Changing strict accessors into silent default providers.** Missing audits must still fail rather than borrowing another target.
7. **Breaking valid exact-zero behavior.** Zero is finite and valid; it must not be treated as missing.
8. **Changing display rounding while fixing non-finite handling.** Keep the current publication convention.
9. **Duplicating finite-number helpers inconsistently.** Use a small internal helper per module or a dependency-free shared utility only if it does not create an undesirable import cycle.

## 10.6 Checks and acceptance criteria

- The exact mutations reproduced in Round 10 no longer leak `ValueError`, `InvalidOperation`, or `AttributeError` from validation entry points.
- Validators return named problem lists.
- Strict accessors raise controlled contextual exceptions.
- Current valid artifacts remain clean.

- No broad exception swallowing is introduced.
